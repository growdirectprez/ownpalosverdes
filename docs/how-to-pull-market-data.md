# How to Pull the Monthly Market Data

The market reports at `/market/YYYY-MM/` are generated by `generate_reports.py` from
CRMLS closed-sales data. This is the one manual step in the pipeline — everything after the
export is automated. Follow this each month (or whenever the reports need to be brought
current) so it never has to be reverse-engineered again.

---

## What the data is

- **Source:** CRMLS **Matrix** → run a search → **Export** to CSV.
- **"Top Producer" is a name, not a tool.** The existing files are named
  `Top Producer - Residential.tp` because that's the **saved export template / saved search**
  name in Matrix — *not* the Top Producer CRM product. Don't look for a "Top Producer" menu
  item; look for that name in Matrix's **Export template dropdown**.
- **Format:** plain CSV using CRMLS/RESO display field names (`Close Date`, `Close Price`,
  `Living Area`, etc.), saved with a `.tp` file extension.

## The exact search (reproduce this in Matrix)

| Filter | Value |
|---|---|
| Property Type | **Single Family Residence** (Property Sub Type) |
| Cities / MLS Areas | **RPV, PVE, RHE, Rolling Hills, PV Peninsula, San Pedro** — MLS areas **160–177** |
| Status | **Closed** (the generator ignores non-closed rows, so "all statuses" is fine too) |
| Date range | For a full rebuild: **2023-07 → present**. For a monthly update: **Close Date ≥ the 1st of the last fully-exported month** (see below). |

## Export steps

1. Run the search above in Matrix.
2. Select the results (checkbox / select-all).
3. Click **Export** in the results toolbar.
4. In the **export-template dropdown**, choose **"Top Producer"** (or "Top Producer -
   Residential"). If it isn't there, it was created under a different Matrix login — use any
   **full / all-fields export**; it just has to include the required columns below.
5. Save the downloaded CSV.

> **500-row limit:** Matrix caps how many rows you can export at once (~500). A full-history
> pull is done in batches — each batch saved as its own file. A monthly update is small
> enough to be a single file.

## Where the files go

- Folder: `~/GrowDirect/Angel/Top Producer - Residential*/` — one export file per folder
  (`Top Producer - Residential`, `-2`, `-3`, … `-7`, …). Add a **new numbered folder** for each
  new export; don't overwrite the old ones.
- **File extension must be `.tp`.** Matrix exports as `.csv`, so rename `something.csv` →
  `Top Producer - Residential.tp` inside the new folder. (Or hand the `.csv` to Claude and it
  will place/rename it.)
- The generator reads **all** `.tp` files and **dedupes by `Listing Id`**, so overlapping
  months across exports never double-count. This is why a monthly update can safely re-include
  the last already-covered month — it fills that month in completely and adds the new ones.

## Required columns (the generator only needs these 14)

```
Listing Id · Close Date · Close Price · City · Zip Code · Bedrooms Total ·
Bathrooms Total Integer · Living Area · Price Per Square Foot · List Price ·
Cumulative Days Active In MLS · Street Number Numeric · Street Name · Year Built
```

Any export template that includes these (with these exact header names) will work.

## Regenerate the site (automated from here)

```bash
cd ~/ownpalosverdes
python3 generate_reports.py        # rebuilds every market/YYYY-MM/ + market/index.html
```

Then, before pushing:

1. **Clear the partial-month flag** if the newly-exported month is now complete: remove that
   month from `PRELIMINARY_MONTHS` near the top of `generate_reports.py`. Add a month there if
   a just-exported month is only partially covered (export taken mid-month).
2. **Add the new month URLs to `sitemap.xml`** — it's hand-maintained (reports use
   `<lastmod>` = month-end; see the existing entries).
3. Commit and push (`main` → GitHub Pages rebuilds). Note the push must go out as the
   `growdirectprez` account — see the project memory / `ownpv-ops`.
4. In **Google Search Console**, submit the new report URLs via **URL Inspection → Request
   Indexing**.

## Cadence

Run this in the **first week after a month closes** (so the prior month's closings are all
recorded in CRMLS). Monthly keeps the archive current and the "preliminary" banner off the
latest report.
