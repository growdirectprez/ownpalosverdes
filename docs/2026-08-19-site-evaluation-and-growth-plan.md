## 3. Attach Google Analytics to Grok

There is an official server: [googleanalytics/google-analytics-mcp](https://github.com/googleanalytics/google-analytics-mcp) (`analytics-mcp`). It is not built into Grok. Drive MCP cannot query GA4.

Tools: account summaries, property details, `run_report`, funnel reports, realtime.

### Steps

1. In a Google Cloud project you own, enable:
   - [Analytics Admin API](https://console.cloud.google.com/apis/library/analyticsadmin.googleapis.com)
   - [Analytics Data API](https://console.cloud.google.com/apis/library/analyticsdata.googleapis.com)

2. Create an OAuth **Desktop** client (APIs & Services → Credentials). Download the JSON.

3. Relogin ADC with the Analytics scope. Use the Google account that can see `G-ZY3DD9BYZ2` in the GA4 UI.

```bash
gcloud auth application-default login \
  --scopes https://www.googleapis.com/auth/analytics.readonly,https://www.googleapis.com/auth/cloud-platform \
  --client-id-file=/path/to/client.json
```

Copy the `Credentials saved to file: [PATH]` location.

4. `brew install pipx && pipx ensurepath` if `pipx` is missing.

5. Register the server in Grok (user-level, not a project `.mcp.json`):

```bash
grok mcp add analytics-mcp \
  -e GOOGLE_APPLICATION_CREDENTIALS=/path/to/application_default_credentials.json \
  -e GOOGLE_PROJECT_ID=YOUR_GCP_PROJECT_ID \
  -- pipx run analytics-mcp
```

Or in `~/.grok/config.toml`:

```toml
[mcp_servers.analytics-mcp]
command = "pipx"
args = ["run", "analytics-mcp"]
env = { GOOGLE_APPLICATION_CREDENTIALS = "/path/to/application_default_credentials.json", GOOGLE_PROJECT_ID = "YOUR_GCP_PROJECT_ID" }
enabled = true
```

6. New Grok session. Confirm with `grok mcp list` and `grok mcp doctor analytics-mcp`. Then re-run the analytics read.

Search Console is a separate MCP if query and indexing data are needed.

## 6. Lead listener — respond or forward

Today a submit goes to Formspree and, unless someone watches that inbox or the
destination email, nothing else happens. There is no auto-reply, no Slack, no
CRM, no `form_type` routing.

### 6A. Stay in Formspree (first)

Turn these on in the `mwvapnan` dashboard. No repo work.

| Plugin | Job |
|---|---|
| Email notification | Confirm it still goes to Angelique (and optionally Geoff). |
| Email routing | Split by `form_type`: valuation / concierge → Angelique; newsletter → list later; contact / quick_connect → same inbox with a prefix. |
| Auto Response | One short ack to the submitter (“I got this, I’ll reply today”). Formspree has this as a plugin. |
| Webhook | POST the JSON to a URL we own, if 6B is approved. Often a paid-tier feature. |
| Zapier / similar | Same as webhook, if we do not want to host an endpoint. |

This is enough if volume is low and Angelique reads email.

### 6B. Automated listener (if we want more than email)

Formspree webhook (or a 5-minute poll of `GET /api/0/forms/mwvapnan/submissions`
with an API token) hits a small always-on function. The function:

1. Verifies the request (shared secret header).
2. Reads `form_type` and the fields already on the page.
3. **Forwards** immediately: email (and optionally Slack / SMS) to Angelique
   with type, name, phone, message, and page URL.
4. **Acks** the submitter with a fixed template. Do not auto-send a drafted
   sales reply until Angelique has approved that voice.
5. Optionally appends a row to a Sheet or Drive folder so we have a durable
   log outside Formspree.
6. Logs `generate_lead` server-side only if we later add Measurement Protocol.
   The browser `gtag` on Formspree `onSuccess` (plan item 2) is the first
   measurement step; this listener does not replace it.

Host: a Cloudflare Worker or Google Apps Script is enough. Do not stand up a
new box. Do not put the Formspree token in the GitHub Pages repo.

**Do not** let an LLM reply to leads unattended on day one. If a draft is
wanted, the listener stores the payload and a human (or a later gated agent)
sends it.

### Decision

Start with 6A the same day the inbox is opened. Build 6B only if submissions
exist and email-only is too slow, or if we want a durable log and typed
routing. Newsletter still belongs on a list tool (item 4), not in this
listener, once that move is made.
